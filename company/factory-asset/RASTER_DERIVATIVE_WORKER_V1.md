# FA-021 raster derivative worker

This Linux worker converts one hash-pinned PNG master to JPEG, WebP or TIFF.
It does not call providers, write production state, evaluate marketplace package
compatibility, or authorize submission. It never changes semantic identity.

## Isolated setup and acceptance

From a fresh Linux checkout:

```sh
python3 -m venv .venv-fa021
.venv-fa021/bin/python -m pip install -r company/factory-asset/requirements-raster-worker.txt
.venv-fa021/bin/python -m pytest -q company/factory-asset/tests
.venv-fa021/bin/python -m pytest -q bridge/tests/test_one_canon_validator_v1.py
.venv-fa021/bin/python company/scripts/validate_one_canon.py --root .
git diff --check
```

Pillow is pinned to 11.3.0. The manifest records the worker, Pillow, JPEG and
WebP codec versions. Byte determinism is claimed for that recorded runtime.
Replay under changed codec versions fails with a collision instead of replacing
an existing output. Runtime upgrades require deliberate recipe/version review.
Dependencies are installed only in the task environment, never system Python.

## API and CLI

Import `convert` from `company/factory-asset/lib/raster_derivative.py`:

```python
result = convert(master_path, recipe, output_root)
```

Or supply a JSON recipe conforming to the FA-020 derivative recipe schema:

```sh
.venv-fa021/bin/python company/factory-asset/bin/derive_raster.py \
  --master /path/to/master.png \
  --recipe /path/to/pinned-recipe.json \
  --output-root /path/to/worker-owned-derivatives
```

Supported recipe version: `1.0.0`. Width, height, color space and alpha policy
must be explicit. JPEG and WebP also require quality; TIFF rejects a quality
field because it uses uncompressed lossless storage. Resizing uses LANCZOS.
JPEG uses 4:4:4 subsampling, no optimization or progressive encoding. WebP
uses lossy encoding, method 6, and exact transparent RGB handling.

Alpha policies:

- `FLATTEN_WHITE`: composite on opaque white, then emit RGB.
- `PRESERVE`: preserve alpha values for WebP/TIFF; reject JPEG.
- `FORBID`: reject a master with an alpha channel or palette transparency.

The bounded v1 subset accepts single-frame RGB/RGBA/P/L/LA PNGs up to 64 MiB
and 25 million pixels. Output is limited to 25 million pixels. A PNG sRGB
chunk is required. ICC-bearing, untagged, conflicting gamma or chromaticity
inputs fail closed; no color conversion is guessed. Output pixels have source
EXIF, ICC, text and DPI metadata removed. The full color/ICC/DPI/metadata
contract remains FA-023 and is not implemented or advanced here.

## Durable output and truthful results

Each idempotency-key directory holds exactly:

- `derivative.jpg`, `derivative.webp` or `derivative.tif`;
- `receipt.json`, validated against the unchanged FA-020 receipt schema;
- `manifest.json`, containing the complete recipe, runtime and metadata policy.

The key hashes canonical JSON containing master SHA-256, recipe ID/version,
marketplace ID/revision and the complete output specification. The master pin
is checked before decode. Output magic, format, decode, dimensions, alpha and
durable bytes/hash are verified before an fsynced staging directory is
published by rename. A Linux flock serializes cooperating writers. Use a
worker-owned output root; concurrent untrusted filesystem writers are outside
this contract.

An existing directory must match the regenerated bytes, receipt and manifest
exactly. Corrupt, partial, symlinked or unrelated targets fail closed without
repair/overwrite. Valid replay returns the durable receipt without rewriting
artifact/receipt/manifest files. A changed semantic parent cannot reuse another
parent's receipt, even when key material and image bytes are identical.

`conversion_status=CREATED|REUSED` and CLI exit 0 mean **conversion completed**.
All conversion QA flags can be true while the canonical receipt has
`result=FAIL` and `compatibility.state=COMPATIBILITY_UNKNOWN`. The current
profile revision and platform ID are checked, but format conversion alone
does not prove marketplace requirements, rights or package readiness. FA-020
requires COMPATIBLE for PASS, so this worker deliberately never mints a
package PASS. The later compatibility gate remains separate and unstarted.

Pre-output failures raise `RasterDerivativeError` with a stable code. The CLI
returns exit 2 with a `FAILED` JSON envelope and no invented artifact or receipt.
The FA-020 receipt requires actual output bytes and a hash; a failed decode
cannot truthfully populate it.

Tests construct tagged, deterministic synthetic masters and cover all three
formats, repeatability, durable receipt validation, alpha/palette behavior,
resizing, malformed/unsupported pins, collisions, concurrent duplicates, disk
failure, CLI replay and preservation of master bytes and timestamps.
