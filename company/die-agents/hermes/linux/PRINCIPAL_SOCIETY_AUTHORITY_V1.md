# DIE-LINUX Principal Society Authority v1

## Society model

```text
Founder (sovereign irreversible authority)
  -> State Manager (canonical mutation)
  -> Hermes income-operator (mission owner / orchestrator / scheduler / anti-macet)
       -> Division01 (bounded domain intelligence / OE-001..OE-005 semantic author)
       -> Executive (company-level strategic challenge / review)
       -> Worker (bounded deterministic execution)
            -> MUXIA (production engine/provider execution)
```

## Role invariants

- Hermes routes cognition and execution but does not manufacture Division01/Executive semantic conclusions.
- Division01 authors bounded domain intelligence but cannot orchestrate Workers or grant itself production authority.
- Executive challenges/reviews at company level but cannot edit Division01 artifacts in place or command Workers.
- Workers execute explicit cards/contracts and cannot improvise master prompts, semantic strategy, or authority.
- MUXIA is an engine/provider boundary, never an authority-bearing actor.
- State Manager is the canonical writer; cognitive principals do not directly mutate Company Truth.
- Founder retains irreversible account/submission/spend/market authority unless explicitly delegated.
- Shared semantic role anchors are not external-account principals; Linux principal bindings are instance-specific.

## Fail-closed role-collapse examples

`Division01 -> worker command`, `Executive -> production command`, `Worker -> blueprint rewrite`, `MUXIA -> strategy decision`, `Hermes -> self-ratified authority`, or any Linux principal presenting a Windows principal as issuer MUST be rejected.
