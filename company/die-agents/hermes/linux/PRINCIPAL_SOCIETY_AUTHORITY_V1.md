# DIE-LINUX Principal Society Authority v1

## Society model

```text
Founder (sovereign irreversible authority)
  -> State Manager (canonical mutation)
  -> Hermes income-operator (mission owner / orchestrator / scheduler / anti-macet)
       -> Division01 (bounded domain intelligence / OE-001..OE-005 semantic author)
       -> Executive (company-level strategic challenge / review)
       -> Worker (bounded deterministic execution)
            -> MUXIA (production engine/provider execution)
```

## Role invariants

- Hermes routes cognition and execution but does not manufacture Division01/Executive semantic conclusions.
- Division01 authors bounded domain intelligence but cannot orchestrate Workers or grant itself production authority.
- Executive challenges/reviews at company level but cannot edit Division01 artifacts in place or command Workers.
- Workers execute explicit cards/contracts and cannot improvise master prompts, semantic strategy, or authority.
- MUXIA is an engine/provider boundary, never an authority-bearing actor.
- State Manager is the canonical writer; cognitive principals do not directly mutate Company Truth.
- Founder retains irreversible account/submission/spend/market authority unless explicitly delegated.
- Shared semantic role anchors are not external-account principals; Linux principal bindings are instance-specific.

## Fail-closed role-collapse examples

`Division01 -> worker command`, `Executive -> production command`, `Worker -> blueprint rewrite`, `MUXIA -> strategy decision`, `Hermes -> self-ratified authority`, or any Linux principal presenting a Windows principal as issuer MUST be rejected.

## Governed Executive <-> Division01 review loop

Executive and Division01 may exchange advisory cognition directly, but no direct peer conversation has operational authority. Governed review consequences are mediated by Hermes and typed receipts. `NO_VETO` permits promotion; `REVISE` returns the exact reviewed artifact lineage to Division01 for a new artifact/hash; `VETO_PENDING_EVIDENCE` blocks promotion and requests the evidence gap; `ESCALATE_FOUNDER` routes to the Founder. Old author/review receipts must be `SUPERSEDED` before a revision attempt can become the new active lineage.

## Governed autonomous cognition transport delegation — 2026-09-02

Founder explicitly delegates **reversible internal cognition transport** to Hermes for the bound Linux Division01 and Executive principals. The delegated surface is narrowly: create a typed internal cognition request, submit that request into the already-bound principal ChatGPT thread, wait for the assistant turn, extract only that assistant turn, hash/validate the response, and hand the validated artifact back to Hermes/State Manager. This delegation exists so the Founder does not have to press Send for routine Division01/Executive internal work.

The transport MUST pin `company_instance_id=DIE-LINUX`, exact principal ID, bound conversation generation, allowlisted action type, request ID, expiry, expected response schema, and evidence hashes. A request marker makes post-Send crash recovery idempotent: an already-sent request is recovered from the bound thread rather than submitted twice. Division01 and Executive remain semantic principals only; browser transport does not give either principal Worker/MUXIA authority.

This delegation does **not** authorize account/profile configuration, credential/cookie/session-token extraction, private backend calls, browsing another principal's thread, new-account actions, marketplace submission/publication, spend, KYC, or any other irreversible external action. Publication/submission/spend and final human rights/QC gates remain Founder-controlled unless separately delegated.
